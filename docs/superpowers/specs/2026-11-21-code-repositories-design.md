# 文件增删行的仓库维度

用户已确认按实际修改文件所属仓库统计，并要求默认仅显示 Agent 总计，点击查看明细后显示 Agent × 仓库。

- 复用现有成功差异计量，先保留逐文件数字证据，再解析各文件所属 Git 仓库；不按会话目录替代文件归属，不持久化新增源码副本。
- 远端主机与仓库路径构成仓库身份，移除协议差异、凭据和 `.git` 后缀；同一仓库多个 worktree 合并。无远端使用 Git common directory 的摘要身份；无法确认时使用“仓库未确定”。
- 一次操作跨仓库时分摊新增、删除和文件修改次数；各仓库分别计一次涉及操作，所以明细的操作次数相加可能大于 Agent 总操作数，行数之和必须一致。
- 保留 `codeChanges` 总计兼容现有接口，在按日历史中增加 `repositoryChanges`；升级缓存并允许相同操作补充更完整的仓库证据，身份与总计不变。
- Codex Desktop 使用版本化独立游标重读保留的原生回执以补齐仓库数据，不重放 LLM/Token。已删除原始日志或无法定位仓库的历史保留未知；本地仓库解析基于采集时现存 Git 元数据。
- 默认只有 Agent 行，每行提供“查看明细/收起明细”。展开内容为该 Agent 的仓库表，支持仓库筛选；日期、语言切换及刷新保留展开状态。所有名称 HTML 转义。
- 验证跨仓库计量、同远端 worktree、本地无远端、错误/缺证据、缓存迁移/重复补采、汇总守恒、默认收起与展开/筛选/日期联动。完成构建、备份安装本机并用真实历史回执验收。
